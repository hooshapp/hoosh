# Physical Android — Ishmum's execution guide

Start with [shared readiness and evidence rules](README.md). All cases begin **NOT RUN**. Run stages in order; record case IDs below with the existing V IDs. Use the normal integrated app, not a seeded QA host. OS labels vary; use the app's own settings handoff to reach the correct permission screen.

## A00 — Install, API and standalone startup (V19–20)

1. **A00.1 Identify:** record phone model, Android/API version, manufacturer, source commit, version/package, signature and APK SHA256. Review any existing `com.hoosh.disconnect.dev` installation before replacing it. Preserve data; stop on signature mismatch instead of uninstalling.
2. **A00.2 Configure/install:** use the reviewed ARM64 internal APK only on a compatible owned test phone. Developer verifies public auth/provider switches and API URL before building. Install/update without clearing data. No debug/test APK or synthetic fixture is required for the user journey.
3. **A00.3 Network:** if tethered local API testing was chosen, a developer may use `adb -s <PHONE_SERIAL> reverse tcp:8000 tcp:8000` for that API only. Verify the exact device first. No Metro reverse is needed. This does not work once USB is disconnected; use approved reachable HTTPS for the unplugged/field pass. Never globally enable cleartext to work around configuration.
4. **A00.4 Launch:** stop Metro, open Hoosh from its icon, background and reopen, then swipe it away and reopen. On a fresh install, intro appears once; three separate upward swipes each play the arrow animation; only after the third animation does Continue appear. Tap Continue → welcome → Sign up. A long swipe counts once, and no fourth swipe is needed. Skip reaches signup. Returning launches do not repeat completed intro. Fonts/images and all normal tabs load.
5. **A00.5 API:** sign-in later must reach real account data; record health/configuration verification separately. A localhost error after OAuth is an auth/callback defect until diagnosed, not proof that the product API is down.

**Exit:** correct normal standalone app starts, backend is reachable in the chosen transport, prior state preserved. If the app requires Metro or shows a QA/pilot screen, stop here.

## A01 — Auth, providers and recovery (V01–05)

1. **A01.1 Fresh signup:** using F, submit empty fields and invalid email first. Errors must be visible and prevent submission. Enter valid name/email/password privately and submit once. Expect check-email guidance, not private Home before confirmation. Do not add a signup age field; current approved signup does not require one.
2. **A01.2 Confirmation:** record whether the email arrives in Inbox/Spam and its actual sender without copying its link. Open the newest confirmation on this same phone/request. Test one warm-app return and, with another fresh request/account, one cold-app return. Expect authenticated intended route and correct identity. An email arriving alone is not a native callback pass.
3. **A01.3 Password login/logout:** invalid password produces a bounded error, no private flash. Valid login shows expected account; record an A/B label instead of email in shared evidence. Logout hides all private tabs/back-stack content. Relaunch while signed out must remain public.
4. **A01.4 Google:** start Continue with Google from login; observe account chooser, choose approved A and complete prompts privately. Expect Hoosh dashboard and matching Settings identity. Repeat from signup; it must not create a second unintended identity. Cancel one attempt, return to app and explicitly clear/cancel the pending request if shown, then start a fresh attempt. Do not reuse an old provider page.
5. **A01.5 Apple OAuth:** perform the same success, cancel and fresh-retry steps using Apple on Android. Expect branded Apple page and correct resulting identity; Hide My Email relay is valid. Apple OAuth on Android does not certify native iPhone Apple sign-in. If a private prompt expires, start again from the app, not browser Refresh.
6. **A01.6 Recovery:** request Forgot password for F. With the newest link on this phone, verify warm and cold returns reach only the authorized reset form. User privately enters/submits the new password. Return to login; new password works, old password fails. Cancel another request; direct reset-page navigation must not authorize a change. Test expired/reused links using disposable requests coordinated by the developer: generic recovery guidance, no private session or second password change. Do not publish links.
7. **A01.7 Network/session:** turn internet off before login and before a pending provider return in separate runs. Expect honest error/pending state, no stale private data. Restore network and retry explicitly. Background/reopen and cold-start a valid signed-in app; correct owner restores. Developer coordinates actual refresh/token-expiry and unavailable-storage tests with sanitized diagnostics; do not edit tokens or clear secure storage manually. If not exercised, mark those rows NOT RUN.
8. **A01.8 Error limits:** rate-limit response behavior can use a developer-controlled fault case; do not repeatedly send emails or guess passwords to trigger it. Record controlled vs physical evidence distinctly.

**Exit:** each enabled provider succeeds on this phone, cancellation is recoverable, email/link and session rows are separately recorded. Backend access, delivery and native return are three distinct observations.

## A02 — Onboarding, profile and saved plan (V06–08)

1. **A02.1 Fresh flow:** start setup with F; record actual screens/order and compare with current Figma reference. Exercise every visible selection/input, Back and Next, required errors and single/multiple-choice rules. Do not claim an absent age/gender/AI feature implemented; record it against the existing product-scope decision if expected.
2. **A02.2 Resume:** leave midway, terminate/reopen and log out/in with the same account. Resume should restore only that account's saved progress. A returning completed account must not be forced into a destructive fresh setup.
3. **A02.3 Plan routes:** exercise manual plan and suggested-plan review using separate disposable accounts or a documented safe restart. Review days, zone, hours, count and minutes. Overnight end must be clearly marked. Change a value, go Back and verify it remains; Save, reopen Settings and cold-start to verify canonical readback. “Generated” presentation alone is not verified AI generation.
4. **A02.4 Draft boundary:** save a new account plan while no protection is installed. Expect saved draft only: no target pause or active status merely from Save, Finish or navigating Home.
5. **A02.5 Profile:** save a harmless synthetic display name, reopen/restart and verify it. Edit then Discard; old value returns. Use the explicit clear control and confirm blank persists. Restore original test value. Test invalid/too-long input using UI limits; errors should not erase the prior saved profile.
6. **A02.6 Conflicts/outage:** on the same A account have the second tester update a draft from another client while the phone has unsaved edits. Save must offer explicit conflict reconciliation, not overwrite silently. Separately stop only the owned API (developer-assisted), try a save, restart it and Check latest/resolve explicitly. Lost write-response requires developer-controlled interruption after commit; no repeated Save guessing. Verify one authoritative result and no auto-Apply.

**Exit:** profile/settings/progress persist for the correct owner, draft differs from installed state, uncertain/conflicting writes are explicitly recoverable.

## A03 — Permissions and selected apps (V09–10)

1. **A03.1 Deny first:** open the in-app protection disclosure, choose Not now/Cancel. Verify no permission is falsely marked granted and ordinary account screens still work.
2. **A03.2 Accessibility:** use Hoosh's disclosure/settings handoff; phone owner enables only Hoosh's protection service. Return to Hoosh and Check/Refresh. Actual OS state must be read; merely visiting Settings does not grant access. Do not enable unrelated services or extra permissions.
3. **A03.3 Usage Access:** separately open Review Usage Access, deny, return/refresh, then grant deliberately and refresh. This is for usage measurement; granting it is not equivalent to enabling protection or applying a plan.
4. **A03.4 Picker Cancel/Save:** note saved count/set. Open native selection, choose T1, then cancel/dismiss. Saved set must remain unchanged. Repeat, confirm choices, then use the editor's explicit Save. Reopen/cold-start; T1 is saved. Add T2 and Save. Native identities must not appear in backend/debug output. Selection alone must not install protection.
5. **A03.5 Permission loss while editing:** begin selection, background to Settings and revoke access, return and attempt Save. Expect truthful refusal/review, no falsely saved selection. Regrant, refresh, repeat explicit Save.
6. **A03.6 Revoke/regrant:** with saved draft/selection, disable protection access and reopen app. Status must become unavailable/disabled, saved draft remains. Regrant and check again; do not assume protection reinstalls silently. Record exact installed status before any explicit Apply.

**Exit:** both permissions have independent honest statuses; saved native app set survives restart; Cancel/Save semantics proven. A denied permission is an expected negative case, not a passing enabled-protection case.

## A04 — Apply, allowance timing and overlapping reasons (V11–12)

1. **A04.1 Explicit Apply:** save the initial test plan from shared controls (currently active window, two allowances, shortest supported duration, T1/T2). Confirm no intervention before Apply. Review and tap Apply once. Record acknowledged installed revision/policy/selection. If uncertain, Check readback before retry. Open T1; real pause/intervention appears.
2. **A04.2 Return home:** choose Return home. Confirm target is left and no allowance was consumed merely by viewing the prompt. Check any earned credit only after server sync per A05.
3. **A04.3 First allowance/reentry:** reopen T1, choose Open anyway/allowed temporary access. Start stopwatch; record count and deadline. Leave/reenter before expiry. Remaining time must decrease from the original deadline, with no second charge/extended deadline. Test T2 separately: per-app allowance counters must not be mistaken for one shared counter.
4. **A04.4 Halfway/expiry:** keep T1 foreground. Observe halfway nudge if applicable; Keep going retains original deadline/count. Keep target foreground past deadline without opening Hoosh. Record actual pause/shield time and drift. Deliberately use Return home on another allowance's nudge to test its separate outcome. No invented success from a timer alone.
5. **A04.5 Daily limit:** consume allowed sessions deliberately and reenter after expiry. Record counter/exhaustion behavior and any explicitly supported extra-access policy against current contract. No reentry/restart/edit/login may silently reset the daily budget or add time. Stop on an undocumented bypass.
6. **A04.6 Draft edit:** change account hours/count/minutes while a native plan is installed; Save must leave installed revision/policy unchanged until explicit review/Apply. A deliberate allowed update preserves already consumed counts/deadlines according to current policy; it does not create a free fresh day.
7. **A04.7 Two-quest overlap:** create two short, future-dated synthetic quests with overlapping windows inside the weekly window. Save alone does not Schedule. Explicitly Schedule both; verify account/device acknowledgment and three active reasons on T1 when all windows overlap. Start sufficiently in the future to complete setup before the window.
8. **A04.8 Scoped Stop:** Stop weekly only. The two quest reasons still protect T1. Stop/cancel the first quest only; second remains. Stop last quest; no remaining reason should block T1. Record before/after installed revisions and allowance count; Stop must not erase history/budget. Exercise one-occurrence cancellation separately from stopping a recurring quest.
9. **A04.9 Edited/recurring quest:** edit a future occurrence and explicitly update schedule. Confirm active occurrence retains reviewed snapshot; future one uses the approved update. Test actual next occurrence/window start and end, not just labels. Longer recurrence/DST cases go to A07 if time has not elapsed.

**Exit:** observed real target timing and reason preservation, not just successful API/native registration. Record each subcase independently.

## A05 — Recommendations, rewards and History (V13–15)

1. **A05.1 Suggestions:** observe recommendation or legitimate cooldown/empty state. Accept once when available; exactly one saved quest appears, cooldown survives reopen, no automatic credit/completion/protection. Skip has the intended cooldown and does not create a quest. Use another disposable eligible account or wait naturally; do not clear cooldown storage to force a result.
2. **A05.2 Quest completion:** let a synthetic scheduled quest end. No automatic completion award. Explicitly confirm eligible completion once; expected +50 server-confirmed quest credits. Reopen/retry/read from another client; no duplicate award. Before-end confirmation must be unavailable/rejected. Do not delete evidence to replay awards.
3. **A05.3 Native earning:** compare wallet before/after explicit Return home at initial pause, halfway and expiry on separate eligible encounters. Current Android policy: +5/+30/+20 respectively, once per encounter/session, 60-second account-wide cooldown. Presentation, Keep going, Open anyway or expiry alone earns nothing. Record cooldown and pending sync; unknown outcomes remain pending. See rewards policy if changed on the candidate.
4. **A05.4 Feed:** with sufficient credits and health below 100, Feed once. Expect -20 credits and up to +20 health, capped 100. Reopen/refresh; same result. Insufficient funds/full health must not spend. Developer-assisted response loss must resolve through Check last Feed, not double spend. Record before/after balance and health; never seed a real account wallet manually.
5. **A05.5 History consent:** Review selected apps → Save, then History disclosure → Not now. No fabricated series/baseline. Start explicitly with Usage Access, check source/coverage and available days. Zero reported days/insufficient baseline must remain unavailable, not 0% savings. Switch 7/28-day views and details.
6. **A05.6 Measurement lifecycle:** revoke Usage Access and refresh; unavailable guidance appears. Stop collection remains usable offline/while revoked; existing account history is not silently deleted. Regrant and explicitly restart. A fixed baseline must not be replaced on ordinary reads/restart. Genuine 7/28-day measurement requires elapsed days; record an ongoing soak instead of synthesizing data.

**Exit:** exact-once visible outcomes and truthful unknown/coverage states; no fake savings or filled streak dots from missing days.

## A06 — Real account ownership and OS lifecycle (V16–20)

1. **A06.1 A→B before claim:** with A's reviewed synthetic rules active, note revision/count/deadline. Logout A: private data hides, installed A rules remain. Sign into distinct B. Verify no A profile, setup answers, draft, quests, rewards, History, selection labels or delayed toasts. B must not automatically manage/ACK A native events. Use different harmless saved values to distinguish accounts.
2. **A06.2 Claim Cancel:** open Use this account on this device and cancel. A rules/count/deadline stay unchanged. B still has no silent ownership.
3. **A06.3 Claim Confirm:** deliberately confirm with the owner. A's active rules stop/archive; private history and budget retained. B sees its own state, no auto-Apply. Test B's explicit selection/plan separately. Return to A; its saved data/counts restore without reactivating old rules or resetting a consumed allowance. Record A→B→A, not just successful sign-outs.
4. **A06.4 Offline:** start an allowance, note deadline/count, turn all internet off, leave T1 foreground through expiry. Actual intervention still occurs. Restore network; readback/sync must not replay Apply or duplicate awards.
5. **A06.5 Host process:** during allowance swipe Hoosh away, then keep T1 foreground through expiry. Separately, a developer may terminate the owned process in a controlled way. Record which process changed; no PID/store dumps containing credentials. Count/deadline must persist without JS/API.
6. **A06.6 Force stop:** separately use Android App info → Force stop on this owned test app, then observe before and after explicitly reopening it. Do not call this an ordinary crash. Record OS/service restrictions honestly; if protection cannot run while force-stopped, classify the supported behavior/limitation before claiming reliability. Never grant via hidden shell commands to conceal it.
7. **A06.7 Lock/reboot/OEM:** lock/unlock during allowance, then separately reboot within an active window. Confirm retained selection, installed revision/count and handling of expired sessions; no new allowance from reboot. Test background/battery-saver/standby with original manufacturer settings first. Record manufacturer intervention and any opt-in battery change; one Pixel result does not pass other OEMs.
8. **A06.8 Upgrade:** install reviewed candidate over the actual previous internal/shipped build in use, preserving data/signature. Verify reauth policy, owner, native revision, pending events and budgets. Never downgrade store readers or clear data to obtain a migration pass. Old Swift/pilot identities are not automatically linked.
9. **A06.9 Delayed responses:** developer coordinates a slow A request/event, logout and B login. Late A responses/callbacks must not appear in B or mutate/ACK its state. A simple network toggle does not prove lost-ACK or delayed-callback isolation by itself.

**Exit:** account and native state remain attributed correctly; actual offline/process/OS observations recorded separately from controlled tests.

## A07 — Layout, real-day soak and handoff (V21; V23 tracked separately)

1. **A07.1 Layout:** walk intro/auth/signup/recovery/setup/plan/Home/Quests/editor/History/Settings on the actual phone. Use larger system text/display size, software keyboard, Back, dirty-edit discard and picker return. Every required control/error/footer remains reachable; no keyboard covers Save or forces unintended submission. Restore settings.
2. **A07.2 Accessibility:** check labels/focus/touch targets and basic TalkBack navigation with a tester actually listening if available. Full speech pass was previously deferred; mark DEFERRED if not run, never infer spoken output from accessibility labels. Expanded V23 retains its separate scope.
3. **A07.3 Soak:** schedule real overnight/day reset, planned-window start/end, recurring quest, extended offline/reconnect and next-day budget checks. Record saved zone and actual dates. DST/travel boundaries need scheduled evidence or explicit pending status; no clock manipulation as a substitute. No seven-day streak/28-day history claim before sufficient real coverage.
4. **A07.4 Cleanup/sign-off:** stop only synthetic plans, restore baseline settings/permissions and remove only this run's reverse mapping (`adb -s <PHONE_SERIAL> reverse --remove tcp:8000`, if created). Preserve records. Complete the shared P08 review with Anisha, list blockers and attach the sanitized run record.

**Exit:** required cases passed on the final candidate or individually blocked/deferred with owners. Physical Android acceptance is scoped to this device/OS/artifact, not every manufacturer or store release.
